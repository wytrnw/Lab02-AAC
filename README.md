Контрольные вопросы:
1. Что такое IL и зачем он нужен между C# и машинным кодом?  
- IL — это промежуточный код, который получается из C# после компиляции. Он не зависит от процессора. Когда программа запускается, JIT-компилятор превращает IL в настоящие машинные инструкции под конкретный процессор.Благодаря этому и можно запустить программу на разных платформах.

2.  Почему .dll можно декомпилировать? 
- Внутри .dll лежит IL-код и метаданные — описание всех классов и методов. Этого достаточно, чтобы ILSpy просто читал их и собирал обратно код, похожий на исходный.(С#)

3.  Какие отличия Debug и Release вы увидели в IL?  
- В Debug есть nop — «пустые» инструкции для отладки, в Release их нет.

В Debug метод Add() сохраняет результат в переменную (stloc.0) и сразу читает её обратно (ldloc.0), в Release это убрано.

В Add() стало меньше инструкций: было 9, стало 4. В SumTo() — было 27, стало 20.

Код Add() стал короче: с 12 до 4 байт.

Условие цикла в SumTo() в Debug занимает четыре команды (cgt, stloc.2, ldloc.2, brtrue.s), а в Release — одну: ble.s.

4.  Почему Release обычно быстрее Debug?  
- В Debug в коде много отладочных команд: nop, лишние сохранения и чтения переменных. В Release компилятор их убирает — метод становится короче и работает быстрее.

5.  Почему строковый пароль в .dll нельзя считать защищённым? 
- 

Строки в .dll хранятся в открытом виде, без шифрования. Любой, кто откроет сборку в HEX-редакторе или декомпиляторе, увидит их. Поэтому компиляция не защищает секреты: пароли и API-ключи нельзя хранить прямо в исходном коде.
